# Dependency refresh, 2026-11-26

Bun's recursive outdated inventory covered the root and full-stack example. The release review used three parallel subagents, grouped by integration, with published manifests, exact npm tarballs, and upstream changelogs. The refresh updated 27 direct dependencies and refreshed transitive packages within their parents' constraints.

## Upgrade decisions

- The major jumps were Babel Parser 8, jest-dom 8, and Happy DOM 21. The Vite alias jumps from 1.2.0 to 8.3.8001 because Vite+ changed its core versioning. Bundled Vite stays on major 8. [Vite+ manifest](https://registry.npmjs.org/vite-plus/1.8.0)
- The evlog CLI crosses two pre-1.0 minor versions. The Static and Router plugins also changed integration behavior within their existing majors. Those changes needed call-site review regardless of version numbering.
- Drizzle ORM and Kit stay paired at 1.0.0-rc.5. RC6 Kit's native Bun migration client omits safe integers, which RC6 ORM requires. In an isolated Bun 1.4.5 probe, Kit's `check` passed on a copy of the example migrations, but `migrate` failed before applying SQL. The same migration passed with the RC5 pair. RC6 also changes raw-query decoding, makes both packages ESM-only, changes Kit's executable, and adds explicit ORM exports alongside its wildcard. [RC6 release](https://github.com/drizzle-team/drizzle-orm/releases/tag/v1.0.0-rc.6) · [Kit tarball](https://registry.npmjs.org/drizzle-kit/-/drizzle-kit-1.0.0-rc.6.tgz) · [ORM tarball](https://registry.npmjs.org/drizzle-orm/-/drizzle-orm-1.0.0-rc.6.tgz)
- Also tested the newest matched beta.2 builds, `1.0.0-beta.2-8a7830c`, in a temporary copy. npm has no unsuffixed beta.2 for either package. Kit's `check` passed, but its native Bun SQLite `migrate` used the PostgreSQL migrator and failed on `CREATE SCHEMA IF NOT EXISTS "drizzle"`. The RC5 control applied the same example migrations and created the expected tables. Stack's export generation also rejected beta.2's explicit export map, which lacks the `drizzle-orm/zod` entry point. The current Better Auth Drizzle adapter's 1.0 peer range starts at RC1. [Beta Kit tarball](https://registry.npmjs.org/drizzle-kit/-/drizzle-kit-1.0.0-beta.2-8a7830c.tgz) · [Beta ORM manifest](https://registry.npmjs.org/drizzle-orm/1.0.0-beta.2-8a7830c) · [Adapter manifest](https://registry.npmjs.org/@better-auth/drizzle-adapter/1.7.28)
- Removed `bumpp` and the direct `exact-mirror` declaration. Release scripts implement version bookkeeping directly. Elysia owns its Exact Mirror dependency. The usage audit retained explicitly supplied peers needed by dependent libraries, including TypeBox, file-type, OpenAPI types, and DOM Testing Library. [Elysia manifest](https://registry.npmjs.org/elysia/1.4.32) · [DOM peer manifest](https://registry.npmjs.org/@testing-library/react/16.3.3)

## Backend, logs, and localization

- **`elysia` 1.4.30 → 1.4.32.** The patch series hardens route, request, and response validation, multipart handling, and signed cookies. The installed Eden and OpenAPI versions accept the new Elysia pin. [Elysia changelog](https://github.com/elysiajs/elysia/blob/e212071ad4197cadcb9d95027ba8b9d1dea9dd20/CHANGELOG.md)
- **`@elysiajs/static` 1.4.10 → 1.4.12.** The plugin now matches exclusions against asset-relative paths. Stack updated the patterns so the transformed HTML shell remains authoritative and files under the reserved API namespace stay excluded. [Static plugin tarball](https://registry.npmjs.org/@elysiajs/static/-/static-1.4.12.tgz)
- **`exact-mirror` 0.2.7 → 0.2.9 in the lockfile.** Elysia installs Exact Mirror through its own `^0.2.9` dependency and uses it to clean data to match TypeBox schemas. The transitive version stays on the legacy TypeBox API. Exact Mirror 1.2.8 targets TypeBox 1.x. [Elysia manifest](https://registry.npmjs.org/elysia/1.4.32) · [Exact Mirror 1.2.8 manifest](https://registry.npmjs.org/exact-mirror/1.2.8)
- **`file-type` 22.2.0 → 22.3.0.** ZIP and EBML probing use bounded reads. Elysia still loads `fileTypeFromBlob` for file validation. [Release comparison](https://github.com/sindresorhus/file-type/compare/v22.2.0...v22.3.0)
- **`better-auth` 1.7.21 → 1.7.28.** The patch series fixes session revocation, OTP resend and collision handling, and organization lifecycle behavior. Stack's session, delivery, and organization wrappers use the same public entry points. [Better Auth changelog](https://github.com/better-auth/better-auth/blob/v1.7.28/packages/better-auth/CHANGELOG.md)
- **`@better-auth/drizzle-adapter` 1.7.21 → 1.7.28.** Fixes joined session reads across schemas and unfiltered relations-v2 queries on Drizzle RC5 and later, including organization member and invitation lists. [Adapter changelog](https://github.com/better-auth/better-auth/blob/v1.7.28/packages/drizzle-adapter/CHANGELOG.md)
- **`auth` 1.7.21 → 1.7.28.** The native CLI expands redaction in its info command and fixes duplicate Prisma back-relations. Stack's Drizzle schema generation still uses `auth/api`. [CLI changelog](https://github.com/better-auth/better-auth/blob/v1.7.28/packages/cli/CHANGELOG.md)
- **`evlog` 2.34.0 → 2.37.1.** Adds pipeline flushing and retry options and fixes rotation when both file limits are configured. The filesystem and toolkit entry points used by Stack remain available. [evlog changelog](https://github.com/evloghq/evlog/blob/evlog%402.37.1/packages/evlog/CHANGELOG.md)
- **`@evlog/cli` 0.11.1 → 0.13.0.** Adds streaming reads, applies repeated `--where` filters, and exits with status 2 on invalid flags. The model-assisted query option is opt-in. Stack's local logging commands use the ordinary CLI. [CLI changelog](https://github.com/evloghq/evlog/blob/%40evlog/cli%400.13.0/packages/cli/CHANGELOG.md)
- **`bullmq` 6.7.6 → 6.7.10.** Updates cron-parser and fixes Postgres queue claim and lock handling. The Redis worker runtime that Stack uses is unchanged in the published JavaScript. [BullMQ changelog](https://github.com/taskforcesh/bullmq/blob/7479e8d73e1740dccd2d0da8053a44b0fb7ada9b/docs/gitbook/changelog.md) · [6.7.9](https://github.com/taskforcesh/bullmq/releases/tag/v6.7.9) · [6.7.10](https://github.com/taskforcesh/bullmq/releases/tag/v6.7.10)
- **`varlock` 1.23.0 → 1.25.0.** Improves injected environment snapshot invalidation, subprocess output, and cache-lock cleanup. Stack's graph and preload entry points still work. The example build regenerated the two environment file headers. [Varlock changelog](https://github.com/dmno-dev/varlock/blob/varlock%401.25.0/packages/varlock/CHANGELOG.md)
- **`gt` 2.28.4 → 2.28.5.** Fixes branch selection and hash reporting for `save-local`. The CLI and the installed runtime adapters still pin `generaltranslation@9.5.13`. [GT change](https://github.com/generaltranslation/gt/pull/2987) · [GT manifest](https://registry.npmjs.org/gt/2.28.5)
