# Use Better Auth for the Auth Block

Applications repeatedly assemble authentication capabilities and their integration code. The Auth Block will use Better Auth, chosen for its developer experience and breadth of authentication and organization capabilities, with prior application usage informing the integration. This accepts coupling to Better Auth's authentication model and plugin ecosystem in exchange for sharing that integration across applications.

The Block is headless and preserves native Better Auth capabilities. Stack owns utilities that remove repeated integration code; applications choose which authentication methods and plugins to enable. Initial organization conveniences cover organizations, membership validation, invitations, and static roles, including server and browser utilities for organization slugs. Organization selection and application policies remain application-owned; richer organization conveniences can follow later.

The initial scope also includes email/password, magic links, email OTP, social sign-on, Elysia session/user utilities, last login method, Drizzle schema generation, doctor integration, and `stack auth` commands. Applications can supply their own email delivery callbacks while the Email Block is deferred. Auth always logs development magic links and OTP codes through Stack's default explicit browser-logging capability, alongside any configured sender such as Mailpit. Development delivery must be excluded from built applications regardless of their runtime mode, and its availability must not prevent builds. The integration should use native tooling boundaries rather than custom source rewriting. [ADR 0021](0021-broadcast-explicit-development-browser-logs.md) records the broadcast and server-console behavior; exact auth callback composition remains under design.

Generate a basic dedicated Drizzle auth schema through Better Auth's generator and keep SQL migration ownership in the Database Block. Applications can build on and extend the schema; extension and regeneration details remain under design. Initial `stack auth` scope covers generation, explicit checks, diagnostics, and secret generation. Doctor remains offline and structural. See the [Auth milestone](../milestones/0007-auth.md) for settled requirements and remaining design questions.
