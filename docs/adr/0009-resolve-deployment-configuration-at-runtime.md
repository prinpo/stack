# Resolve deployment configuration at runtime

Use Varlock as the standard configuration lifecycle for Stack server startup, and retain independently usable environment helpers for schema-driven loading, validation, typed access, and public/secret classification. Preserve native Varlock concepts and APIs with minimal integration code; external secret providers remain optional. This accepts Varlock's schema language and loading lifecycle in exchange for flexible configuration resolution beyond typed validation alone, following the dependency ownership and independent Block boundaries in ADRs 0001 and 0002.

Browser and backend builds must succeed without deployment credentials. Credentials are resolved and validated at runtime rather than embedded in build artifacts, allowing the same built artifacts, including a container image, to be used across deployments. Public configuration may be committed and static when its value is intended to be fixed in the artifact; deployment-specific values must remain dynamic. Builds validate the static configuration they need without requiring dynamic values; the concrete mechanism for skipping dynamic resolution while preserving schema metadata remains to be verified.

Static configuration must not depend on dynamic configuration; a value with a dynamic dependency must itself be dynamic. Prefer an early configuration error for this violation if upstream metadata makes a small, reliable check feasible, without committing to a custom dependency analyzer.

Use two independent schema directories, client and server, with values beside their declarations. Vite resolves client dynamics directly during development; production startup resolves them into a dedicated snapshot using the active server profile, without importing client definitions into the server schema or overwriting the native server ENV store. Derive exposure from explicitly public client metadata rather than repeating key lists in applications. Stack owns validation and defaults for HOST=127.0.0.1, PORT=3000, and NODE_ENV=development; apps override values without declaring those types again. Keep locally generated typed access for application settings. Sensitive defaults remain dynamic; public exposure requires an explicit declaration, and public values may be static or dynamic independently of file commitment.

Resolve and validate required runtime configuration at server startup before accepting traffic. Use `startServer` to initialize configuration before importing application modules and opening a listener. Reuse existing validated native CLI snapshots to avoid resolving providers twice. Bun dotenv loading stays disabled. Production profile selection and existing build commands remain native until the planned Stack CLI owns them; this change does not implement that CLI. Backend changes, including credential rotation, require an instance restart. Development client values are read when Vite prepares HTML; production client values remain startup snapshots.

Deliver public dynamic browser configuration in the initial HTML, before application modules evaluate, using Varlock's native boot-time hydration global. This replaces the initial endpoint-fetch/bootstrap-split decision: applications keep one ordinary browser entry point in development and production, with no browser configuration request or configuration retry UI. During development, `stack({ api: true })` reads only backend connection settings from server files and uses the derived address only for API proxying. It resolves the public client schema and values locally, so serving HTML requires no backend configuration request or running backend. During production startup, the standard HTML transform uses Bun HTMLRewriter to prepare an in-memory shell once, leaving build artifacts unchanged. Derive standard HTML exposure from the client schema. Register no environment endpoint. Remove retired endpoint and manual hydration helpers rather than keeping compatibility wrappers for the abandoned transport. Serve the prepared shell consistently at root, explicit index, and SPA deep links without caching deployment-specific HTML. This preserves credential-free builds and reusable artifacts, verified by serving one browser build under different runtime configurations.

The effective client schema must contain only explicitly public values, including imported definitions. Sensitive values, whether static or dynamic, do not belong in the client graph; prefer an early configuration error when this can be enforced reliably. This is a requirement to verify, not a claim of native enforcement already present in Varlock.

Client exposure and static/dynamic classification must be inspectable without resolving runtime values. Reject runtime-dependent classification rather than fetching credentials to discover whether a client entry is permitted. Backend schemas retain native Varlock flexibility, subject to the static-dependency rule for credential-free builds.

Disable Varlock's automatic log/output redaction and response leak detection in the documented integration with `@redact=false` and `@preventLeaks=false`. Applications own the responsibility to avoid logging or returning secrets; Stack adds no Varlock-aware logger drain or redaction layer. This chooses explicit application discipline over automatic output interception given unmeasured performance and compatibility concerns with the existing logging integration. No evlog incompatibility has been demonstrated. Applications may enable these native protections experimentally at their own risk; this milestone does not qualify those opt-ins with evlog.

Stack owns pinned Varlock core and Vite integration dependencies. Optional provider plugins and their authentication configuration belong to consuming applications; Stack does not bundle or qualify every provider combination.

The compatibility gate originally required core static-only loading and Vite/Rolldown entry-metadata patches. Keep the core patch and its regression checks. Retire the Vite metadata patch now that HTML supplies metadata before module evaluation; the emitted-module probe qualifies the unpatched Vite integration. Document that patched dependency manifests do not apply transitively, and independently installed package qualification remains deferred under ADR 0004.
