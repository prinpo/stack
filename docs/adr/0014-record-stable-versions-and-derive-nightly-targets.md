# Record stable versions and derive nightly targets

Store the last stable release in the root manifest instead of manually maintaining the next intended version. Nightlies automatically add one patch before adding their date/run suffix, and do not commit a version update. `latest` promotes the highest successful nightly's exact source commit, defaulting to its previewed normal version. Allow an optional plain stable-version override for minor or major releases; reject that input for nightlies and reject any target at or below an already released normal version. This follows T3 Code's version model and supersedes the manual manifest-bump policy in ADR 0011 and the strictly channel-only form in ADR 0013.

After npm submission and GitHub Release publication succeed, a separate GitHub-hosted finalizer commits the normal version in the root manifest and pushes with a short-lived Release App token. The Bun lockfile does not record the root package version. The finalizer starts from current `main`, retries concurrent pushes by reapplying its limited change without force-pushing, and is idempotent. If it fails, retry its bookkeeping without republishing. Stale nightly targets stay blocked in the meantime.

Keep `Check` required on `main`. Grant the repository-scoped Release App bypass for that rule so the version commit can land and trigger normal push CI. Keep branch deletion and force-push protections outside its bypass. Keep the self-hosted preparation runner read-only and retain npm OIDC and the fresh-nightly requirement after workflow-file changes.
