# Record stable versions and derive nightly targets

Store the last stable release in the root manifest instead of manually maintaining the next intended version. Nightlies automatically add one patch before adding their date/run suffix, and do not commit a version update. `latest` promotes the highest successful nightly's exact source commit, defaulting to its previewed normal version. Allow an optional plain stable-version override for minor or major releases; reject that input for nightlies and reject any target at or below an already released normal version. This follows T3 Code's version model and supersedes the manual manifest-bump policy in ADR 0011 and the strictly channel-only form in ADR 0013.

After npm submission and GitHub Release publication succeed, a separate GitHub-hosted finalizer records the normal version in the root manifest, refreshes the Bun lockfile, validates the checkout, commits and pushes with the built-in GitHub token. The private example is not a versioned package. The finalizer starts from current `main`, retries concurrent pushes by reapplying its limited change without force-pushing, and is idempotent. If it fails, retry its bookkeeping without republishing; block stale nightly targets in the meantime.

The current branch rules permit this with ordinary Contents write permission, so no PAT, GitHub App or new secret is needed. Built-in-token pushes do not trigger ordinary push CI; the finalizer runs checks itself. Keep the self-hosted preparation runner read-only and retain npm OIDC and the fresh-nightly requirement after workflow-file changes.
