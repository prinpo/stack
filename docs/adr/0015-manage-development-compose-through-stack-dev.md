# Manage development Compose through Stack dev

Applications currently start local dependencies manually before starting development. Detect exactly `docker-compose.dev.yml` in the application root where `stack dev` runs, and automatically start the whole Compose project before launching application processes. This brings development Compose into scope from ADR 0010's deferred Docker workflows, independently of the database Block. Without that file, development performs no Docker checks or operations.

Check Docker CLI, Compose, and daemon access, and launch application processes only after dependencies are ready. Use Compose's native waiting behavior with a 120-second readiness timeout; image pulls and builds can take additional time. Healthchecks determine readiness where provided; otherwise a service must be running. Report prerequisite failures clearly; otherwise print Compose's own launch errors without attempting to diagnose them. Developers own Compose environment configuration; Stack adds no automatic environment loading or forwarding policy for Compose. Use normal Compose service and profile selection without selecting services or activating additional profiles on the developer's behalf.

The development session manages the whole Compose project and stops its services on exit, including services already running before the session. Stop preserves containers and data while allowing processes to shut down, rather than freezing them through pause. Reject overlapping Stack development sessions managing the same Compose project. Keep dependencies running across application restarts, and leave ongoing container supervision to Docker and the application after startup readiness succeeds.

Once Compose startup begins, attempt to stop the whole project on failed or interrupted startup, including partial startup. Prerequisite-check failures alone do not trigger a stop. On session shutdown, stop application processes before Compose services. Make one bounded cleanup attempt and print cleanup errors without hiding the original failure or interrupt status; cleanup failure makes an otherwise successful exit unsuccessful.

Initially, leave manually paused containers to Compose's normal behavior and report resulting startup or readiness errors rather than automatically unpausing them. Changes to the Compose file require restarting `stack dev`; do not watch the file or automatically reconfigure infrastructure during a session.
