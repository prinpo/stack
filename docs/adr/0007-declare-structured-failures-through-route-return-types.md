# Declare structured failures through route return types

Stack's evlog integration exposes expected structured failures through the request-context `apiError` helper used in route return expressions so Eden can infer each route's error branches. The helper advertises a native Elysia status-response type while internally throwing through evlog, combining evlog's error lifecycle with Elysia's route inference; the plugin's serializer must honor the advertised status and public body. This chooses an intentionally declared response contract over relying on the inferred `never` type of a throwing function, which does not describe the route's failure to clients. Trust this TypeScript contract without an additional backend response-validation pass; document that explicit conflicting response schemas or application error handlers can override it, while client guard validation remains separate.
